# Login Checklist — Чек-лист тестирования авторизации

## 1. Общая информация

**Объект тестирования:** форма авторизации веб-приложения.

**Тип тестирования:** функциональное, UI, негативное, позитивное, проверка безопасности.

**Цель:** проверить корректность работы формы авторизации, валидацию входных данных и обработку ошибок.

## 2. Предусловия

- Открыта страница авторизации.
- Существует зарегистрированный тестовый пользователь `valid_user`.
- Для тестирования доступен корректный пароль пользователя.
- Проверки выполняются в браузере Chrome.

## 3. Чек-лист

### 3.1. Проверка интерфейса

- [ ] Страница авторизации открывается без ошибок.
- [ ] Отображается поле ввода логина.
- [ ] Отображается поле ввода пароля.
- [ ] Отображается кнопка «Войти».
- [ ] Поля и кнопка отображаются корректно.
- [ ] Пароль по умолчанию скрыт маской.
- [ ] Кнопка отображения пароля переключает видимость символов.

### 3.2. Проверка позитивных сценариев

- [ ] Авторизация выполняется с корректным логином и паролем.
- [ ] После успешной авторизации пользователь перенаправляется в личный кабинет.
- [ ] Авторизация запускается нажатием кнопки «Войти».
- [ ] Авторизация запускается нажатием клавиши Enter.

### 3.3. Проверка негативных сценариев

- [ ] Авторизация не выполняется при неверном пароле.
- [ ] Авторизация не выполняется при незарегистрированном логине.
- [ ] Авторизация не выполняется при пустом поле логина.
- [ ] Авторизация не выполняется при пустом поле пароля.
- [ ] При пустом логине отображается сообщение «Введите логин».
- [ ] При пустом пароле отображается сообщение «Введите пароль».
- [ ] Логин длиной менее 3 символов отклоняется.
- [ ] Логин длиной более 20 символов отклоняется.
- [ ] Логин с кириллицей отклоняется.
- [ ] Логин с цифрами отклоняется.
- [ ] Логин с пробелами отклоняется.
- [ ] Логин со специальными символами отклоняется.
- [ ] Логин с эмодзи отклоняется.
- [ ] Учитывается регистр символов логина.

### 3.4. Проверка безопасности

- [ ] Ввод HTML/JavaScript-строки в поле логина не приводит к выполнению кода.
- [ ] Ввод HTML/JavaScript-строки в поле пароля не приводит к выполнению кода.
- [ ] Пароль не отображается открытым текстом без включения соответствующей настройки.
- [ ] В сообщениях об ошибке не раскрывается, существует ли введённый логин.

### 3.5. Проверка стабильности

- [ ] Многократное нажатие кнопки «Войти» не приводит к дублированию запросов авторизации.
- [ ] После неудачной попытки авторизации форма остаётся доступной для повторного ввода данных.
- [ ] Ошибки авторизации не приводят к зависанию или аварийному завершению приложения.

## 4. Примечания

- Чек-лист составлен на основе требований учебного приложения.
- Фактическое выполнение проверок не заявляется: документ предназначен для демонстрации навыков составления тестовой документации.
- Точные сообщения и поведение интерфейса должны сверяться с требованиями конкретного приложения.
