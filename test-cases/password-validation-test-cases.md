# Password Validation — Test Cases

## 1. Общая информация

**Объект тестирования:** форма создания нового пароля.

**Тип тестирования:** функциональное, негативное, позитивное, граничное, проверка безопасности.

**Цель:** проверить соблюдение требований к длине и составу пароля, а также корректную обработку некорректного ввода.

## 2. Требования

1. Минимальная длина пароля — 8 символов.
2. Максимальная длина пароля — 20 символов.
3. Разрешены английские буквы (A–Z, a–z), цифры и специальные символы.
4. Кириллица, пробелы и эмодзи запрещены.
5. Пароль не должен отображаться открытым текстом по умолчанию.
6. При некорректном вводе система должна показывать сообщение об ошибке и не позволять создать пароль.

**Примечание:** требования описывают учебное приложение и используются как основа для тестирования.

## 3. Тестовые данные

- `Valid123!` — допустимый пароль длиной 9 символов.
- `Abc123!` — пароль длиной 7 символов.
- `Abcdef12` — пароль длиной 8 символов.
- `Abcdef123` — пароль длиной 9 символов.
- `Abcdefghijklmnopqrs` — пароль длиной 19 символов.
- `Abcdefghijklmnopqrs1` — пароль длиной 20 символов.
- `Abcdefghijklmnopqrst1` — пароль длиной 21 символ.
- `ТестPass123!` — пароль с кириллицей.
- `Test Pass123!` — пароль с пробелом.
- `TestPass123😀` — пароль с эмодзи.
- `<script>alert(1)</script>` — тестовая строка для проверки безопасности.

**Предусловие:** открыта форма создания пароля.

**Шаги:**
1. Ввести пароль `Valid123!`.
2. Подтвердить создание пароля.

**Ожидаемый результат:**
- Пароль принимается системой.
- Пароль успешно создаётся.
- Ошибки валидации не отображаются.

### TC-15 — Проверка обработки потенциально опасной строки

2. Проверить поведение формы.
3. Попытаться создать пароль.

**Ожидаемый результат:**
- JavaScript-код не выполняется.
- Всплывающее окно `alert` не появляется.
- Приложение продолжает работать корректно.
- Некорректный пароль не создаётся.

## 5. Примечания

- Точные тексты сообщений об ошибках не заданы требованиями, поэтому проверяется смысл сообщения, а не его дословная формулировка.
- В тест-кейсах предполагается, что форма позволяет проверить пароль и отправить его на создание.
- Проверка безопасности не заменяет полноценное тестирование на XSS и другие уязвимости.
