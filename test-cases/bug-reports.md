# Bug Reports — Учебные примеры

## Общая информация

**Проект:** учебное веб-приложение авторизации.

**Тип документа:** примеры оформления дефектов.

**Примечание:** все дефекты и фактические результаты в этом файле смоделированы для учебного портфолио.

---

## BUG-001 — Авторизация выполняется с неверным паролем

**Severity:** Critical  
**Priority:** High  
**Тип:** Functional  
**Окружение:** Web, Chrome

**Предусловие:** зарегистрирован пользователь `validuser` с установленным паролем.

**Шаги воспроизведения:**
1. Открыть страницу авторизации.
2. Ввести логин `validuser`.
3. Ввести неверный пароль `WrongPass123!`.
4. Нажать кнопку «Войти».

**Ожидаемый результат:** авторизация не выполняется. Пользователь остаётся на странице входа и видит сообщение об ошибке авторизации.

**Фактический результат:** авторизация выполняется, пользователь получает доступ к личному кабинету с неверным паролем.

**Комментарий:** дефект нарушает основной механизм аутентификации и может привести к несанкционированному доступу.

## BUG-002 — Форма входа не отправляется при нажатии Enter

**Severity:** Medium  
**Priority:** Medium  
**Тип:** Functional  
**Окружение:** Web, Chrome

**Предусловие:** открыта страница авторизации. Есть зарегистрированный пользователь.

**Шаги воспроизведения:**
1. Ввести корректный логин.
2. Ввести корректный пароль.
3. Установить курсор в поле пароля.
4. Нажать клавишу Enter.

**Ожидаемый результат:** форма отправляется, пользователь авторизуется и переходит в личный кабинет.

**Фактический результат:** нажатие Enter не отправляет форму. Для авторизации необходимо нажать кнопку «Войти» мышью.

**Комментарий:** пользователь не может отправить форму с клавиатуры предусмотренным способом.

## BUG-003 — Поле пароля по умолчанию показывает введённые символы

**Severity:** Medium  
**Priority:** High  
**Тип:** Security / UI  
**Окружение:** Web, Chrome

**Предусловие:** открыта страница авторизации.

**Шаги воспроизведения:**
1. Ввести пароль в поле пароля.
2. Проверить отображение введённых символов.

**Ожидаемый результат:** пароль по умолчанию отображается в виде маскированных символов.

**Фактический результат:** введённый пароль отображается открытым текстом.

**Комментарий:** пароль могут увидеть люди рядом с пользователем.

## BUG-004 — Форма отправляет запрос авторизации с логином из 21 символа

**Severity:** Medium  
**Priority:** Medium  
**Тип:** Functional / Validation  
**Окружение:** Web, Chrome

**Предусловие:** открыта страница авторизации.

**Шаги воспроизведения:**
1. Ввести логин `abcdefghijklmnopqrstu` (21 латинская буква).
2. Ввести пароль.
3. Нажать кнопку «Войти».

**Ожидаемый результат:** авторизация не выполняется. Отображается сообщение о превышении допустимой длины логина.

**Фактический результат:** форма принимает логин длиной 21 символ и отправляет запрос авторизации. Сообщение о превышении длины не отображается.

**Комментарий:** не соблюдается ограничение максимальной длины логина в 20 символов.

**Окружение:** Web, Chrome

## BUG-007 — Быстрые повторные нажатия «Войти» отправляют несколько запросов

**Severity:** Medium  
**Priority:** Medium  
**Тип:** Functional  
**Окружение:** Web, Chrome

**Предусловие:** открыта страница авторизации. В Chrome DevTools открыта вкладка Network.

**Шаги воспроизведения:**
1. Ввести корректный логин и пароль.
2. Быстро нажать кнопку «Войти» несколько раз подряд.
3. Проверить количество запросов авторизации во вкладке Network.

**Ожидаемый результат:** отправляется один запрос авторизации.

**Фактический результат:** при каждом нажатии отправляется отдельный запрос авторизации.

**Комментарий:** дублирующиеся запросы создают лишнюю нагрузку и могут приводить к некорректному поведению интерфейса.

## BUG-008 — Форма входа небезопасно отображает пользовательский ввод

**Severity:** Critical  
**Priority:** High  
**Тип:** Security / XSS  
**Окружение:** Web, Chrome

**Контекст:** учебный пример дефекта обработки данных из поля логина.

**Ожидаемый результат:** приложение отображает введённое значение как обычный текст. Браузер не интерпретирует его как код.

**Фактический результат в учебном сценарии:** браузер интерпретирует часть пользовательского ввода как JavaScript и выполняет его в контексте страницы.

**Комментарий:** требуется проверить, как приложение выводит пользовательские данные, и убедиться, что они экранируются в соответствии с контекстом вывода.

## Примечание

Severity отражает степень влияния дефекта на работу приложения.

Priority отражает срочность исправления дефекта.
